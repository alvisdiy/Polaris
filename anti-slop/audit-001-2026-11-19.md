## What is already right

Do not regress these while fixing the list below:

- Type system is specific and consistent: Fraunces display, Instrument Sans body,
  IBM Plex Mono for machine facts. No Inter, no browser defaults.
- One accent (vermilion), warm neutrals, no purple gradient, no pure black.
- Paper grain and two soft radial washes give the surface depth without noise.
- Provenance is visible in the UI: source host on every card, "not stated" instead
  of invented values, expired records marked as archive.
- Loading, empty, and error states exist for every data surface, with skeletons
  shaped like the content.
- Focus rings, skip link, `aria-live` result counts, deadline state carried by
  icon + word + colour, reduced-motion handling.
- Asymmetry is already the default on detail, match, and about pages.

## Findings, in fix order

### Priority 1 — functional and access defects

**1. Saved is unreachable from desktop navigation.**
`NavBar.vue` links: Browse, Match, Compare, About. `MobileMenuSheet.vue` adds Saved.
`FooterBar.vue` does not link it either. On desktop the shortlist has no entry point.
Fix: add Saved to the primary nav (with the same count badge) or to the footer;
keep one of the two so the nav does not grow to five items on narrow laptops.

**2. No search on mobile.**
`GlobalSearch` is `display: none` below 720px, and the mobile sheet has no search
field. A phone user can only search after reaching Discover.
Fix: put a search input at the top of the mobile sheet, submitting to
`/discover?q=…`. Keep the sheet's focus trap in mind when adding it.

**3. Global search reloads the whole app.**
`NavBar.submitSearch()` uses `window.location.assign(...)`. That throws away the
SPA, re-downloads fonts and the bundle, and loses scroll state.
Fix: `router.push({ path: '/discover', query: { q } })`; Discover already treats
the URL as the source of truth.

**4. Mobile menu is visually a dialog but not semantically one.**
`MobileMenuSheet.vue` renders an overlay `div` around a `<nav>`; it has Escape and
a Tab trap, but no `role="dialog"`, no `aria-modal="true"`, no accessible name, and
the page behind stays in the accessibility tree.
Fix: `role="dialog" aria-modal="true" aria-labelledby="menu-title"`, give the
wordmark an id, and set `inert` (or `aria-hidden`) on `#app` while open. Restore
the previous `body.overflow` value instead of clearing it.

**5. Dark theme: white on vermilion is 3.18:1.**
Measured `#ffffff` on `--color-brand` `#E0704F` = 3.18:1. Affects the compare
count badge (0.62rem) and `.button-primary:hover` in dark mode. Light mode passes
(5.52:1).
Fix: add `--color-on-brand` (`#ffffff` light, `#14110D` dark — 5.92:1). Do not
change the accent itself; it is the identity.

**6. Theme is applied after first paint.**
`stores/theme.ts` sets `data-theme` in a `watchEffect` during module evaluation,
which runs after the stylesheet has painted. A dark-theme user sees a cream flash
on every hard load. It also ignores `prefers-color-scheme`: an OS-dark user with
no stored choice gets light.
Fix: inline pre-paint script in `index.html` that reads `polaris.theme` (falling
back to `matchMedia('(prefers-color-scheme: dark)')`) and sets `documentElement.dataset.theme`
before CSS; add `<meta name="color-scheme" content="light dark">`. Keep the store
as the single writer afterwards, and guard `localStorage` access.

**7. Skip link does not move focus reliably.**
`App.vue` targets `#main-content`, but the `<main>` is not focusable. Some
browsers scroll without moving focus, so the next Tab returns to the nav.
Fix: `<main id="main-content" tabindex="-1">` and remove the outline on that
element only (`#main-content:focus { outline: none }`).

### Priority 2 — the page still reads as a template in two places

**8. Home "How Polaris works" is a three-equal-column row.**
`HomeView.vue` uses `grid-template-columns: repeat(3, 1fr)` with three identical
steps. This is the exact pattern `DESIGN.md` §5 bans, and it flattens the
asymmetric editorial rhythm the hero establishes. The numbers `01/02/03` are the
only ordering cue, so the eye reads three cards, not a sequence.
Fix: one column of three numbered, rule-separated entries with the section title
sticky on the left (2/3 + 1/3 split), or a 2-column zig-zag with the third entry
full width. Keep the numbers; drop the equal card rhythm.

**9. Home examples row is three equal cards.**
`examples-grid` is `repeat(3, 1fr)` fed by `limit: 3`. With fewer than three
records the row leaves a hole; with three it reads as the generic feature row.
Fix: make the first record a wide lead card (2/3) and the other two stacked in the
remaining 1/3, or use a rule-separated list where each record is a row. Either
keeps the ledger feel and removes the empty-cell case.

**10. Mobile Discover opens on a wall of filters.**
Below 900px the rail becomes `position: static`, so three controls and a note sit
above the first result on every visit.
Fix: collapse the rail into a disclosure (`<details>` with "Filters" and a count
of active filters) under 900px; keep it open on desktop. The active-filter chips
already communicate state, so the collapsed view is not lossy.

**11. Compare is a dead end once two items are selected.**
With 2–4 columns loaded there is no control to add another; the user must go back
to Browse and find a card checkbox.
Fix: an "Add scholarship" link to `/discover` next to the selection note, and keep
the 4-item limit message. (The per-column error does have a retry in the stacked
view, so that part is fine.)

### Priority 2 — polish that shows at normal reading size

**12. Typographic finishing.**
- No `text-wrap: balance` on `h1`/`h2`, so short headlines can orphan a word
  ("source." in the hero is one resize away). Add balance to headings and
  `text-wrap: pretty` to paragraphs.
- Machine metadata runs at 0.62–0.68rem (≈10px) in uppercase with 0.08–0.18em
  tracking — the smallest text in the product sits in the least legible style.
  Raise the floor to 0.7rem and keep tracking in a token (`--tracking-label`)
  instead of six ad-hoc values.
- `App.vue` uses `min-height: calc(100vh - 8rem)`. Use `100dvh` so iOS Safari does
  not jump when the URL bar collapses.

**13. Cards only react to hover.**
`ScholarshipCard` lifts and turns its top edge vermilion on `:hover`; keyboard
focus inside the card gives no equivalent. Add `:focus-within` with the same lift
and edge colour. This is the difference between "alive" and "alive for mouse users".

**14. Skeleton shimmer repaints instead of compositing.**
`SkeletonBlock.vue` animates `background-position` at 1.4s infinite, which
`DESIGN.md` §4 explicitly rules out ("shimmer via transform only").
Fix: a pseudo-element gradient translated with `transform: translateX(-100% → 100%)`
inside `overflow: hidden`. Same look, no per-frame paint.

### Priority 2 — weight and launch readiness

**15. The globe costs more than the rest of the landing page.**
`three` ships a 753 kB chunk for one decorative, `aria-hidden` element, and it is
the reason `vue-tsc --noEmit` fails (`HeroGlobe.vue:27`, no types for `three`).
The design language is lines, dots, and rules — a globe is the least "ledger"
element on the page.
Fix (recommended): replace with an inline SVG or 2D canvas wireframe, no
dependency, no type gap. Alternative: keep it, dynamic-import on idle/intersection,
add `@types/three` — still 753 kB.

**16. Font payload is heavier than the design needs.**
Three Google families in one render-blocking stylesheet, including weights the
interface may not use (Fraunces 400/700, Plex 600).
Fix: inventory the weights actually rendered, drop the rest, self-host woff2
(Fraunces is variable), or load the stylesheet non-blocking. Keep `display=swap`.

**17. Shared links have no face.**
No `public/` directory, no favicon, no `og:*` or `twitter:card`, and `<title>` is
the same on every route. A link posted anywhere renders as a bare URL.
Fix: `favicon.svg` (+ `apple-touch-icon`), a 1200×630 OG image in the paper/ink
palette, per-route `meta.title`/`description` applied in `router.afterEach`, and
static OG tags for the home route.

**18. No legal surface.**
Footer has Browse, Match, About. There is no privacy or terms route, and the app
stores a shortlist and a theme in `localStorage` — which is exactly what a privacy
note should disclose.
Fix: minimal `/privacy` and `/terms` pages in the same prose style, footer links,
and a sentence about local storage on the privacy page. No cookie banner needed
unless analytics are added.

### Priority 3 — correctness details worth batching

**19. Discover can fire three or four identical requests per interaction.**
`watch(q)` (debounced), `watch([country, degree])`, `watch(page)`, and the clear
buttons each call `syncUrl()` and `fetchCurrent()`. Changing country while on page
2 triggers the country watcher and the page watcher; `clearFilters()` triggers the
three field watchers plus its own fetch.
Fix: one watcher on the derived query object (q, country, degree, page) that syncs
the URL and fetches once, with a request sequence guard so a slow earlier response
cannot overwrite a newer one.

**20. Three small defects.**
- `ScholarshipDetailView`: `.button-demoted` cannot beat `.button-primary:hover`
  (0,1,0 vs 0,2,0), so the expired record's CTA turns vermilion on hover — the one
  action that should stay quiet. Scope the demoted state with
  `.button-primary.button-demoted` and a matching hover.
- `SavedView.retry()` sets `state = 'loading'` and then calls
  `window.location.reload()`; the state assignment is dead and the reload is a
  full app restart for one failed list.
- `MatchView` idle state passes `<template />` to `EmptyState`; the actions wrapper
  can render as empty space. Use `v-if` on the wrapper or omit the slot.
