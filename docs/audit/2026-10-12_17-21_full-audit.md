## 1. EXECUTIVE SUMMARY

**Polaris is a real, working backend for official-source scholarship ingestion + deterministic matching, with a Vue frontend shell and a newly added review/curation surface.** The repository is far past a skeleton: 1,522 tests run green (6 skipped), the matching pipeline, publication boundary, vocabulary system, deadline-contradiction detection, source/provider registration, and the country-exploration loop are all implemented and tested.

**What is genuinely proven working:**
- Public matching API (`POST /api/v1/recommendations` + legacy `/api/v1/matching`) returns ranked, explained scholarships from approved records only; 200 with correct schema, 422 on bad input, 404 on unknown/malformed ids, and it never leaks unpublished rows or `"Unknown"` sentinels into responses.
- Publication boundary is enforced from **one predicate** (`services/review/publication.py`), used by repository read paths, matching, and API; review rows are invisible to the public.
- Controlled vocabulary is a **single canonical definition** (`services/domain/vocabulary.py`) shared by API schema, ingestion validator, matching normalizer, review service, and the DB constraint. "Polytechnic"/"Diploma" are refused; "Doctorate" no longer exists as a divergent value.
- Deterministic extraction client (`DeterministicLLMClient`) no longer fabricates names: unidentifiable pages yield `name=None`; deadline contradictions are detected and either resolved (superseded) or block with a conflict.
- Review/curation service owns the `extraction_status` state machine, writes version + audit rows together, gates approval on a quality report, and exposes an admin API (`/api/v1/admin/review/*`) with proper 409/422 semantics.
- Country exploration engine (`CountryExplorationEngine`) runs a bounded frontier loop: search → candidates → fetch/analyze → classify → provider resolve → authority → verify → register source → acquire → expand links. There is a fake-provider end-to-end test proving the loop with zero seeds.
- Security boundaries exist and are tested: URL safety (SSRF), robots.txt, untrusted-content injection markers, fetch safety with bounded retry.

**What is still half-done / unverified against real data:**
- **Discovery is mock-only in the test suite.** The full-loop test uses `FakeSearchProvider` + `FakeAnalyzer` with canned HTML. There is no test proving the system discovers a *new* source from a country that wasn't pre-seeded, because that would require a real search backend. The architecture is there; the live-discovery proof is not.
- **Real-data acquisition is scripted, not continuously running.** There are many `scripts/m*`, `scripts/v*`, `scripts/p*` audit/run scripts, and metric JSONs in `docs/progress/` and root — evidence of real runs — but those are procedural scripts, not an automated pipeline job wired into the app.
- **Frontend is a shell + partial views.** New components exist (ScholarshipCard, ExplanationPanel, FilterChip, etc.) and the router/views are added, but `App.vue` is in a large unreviewed diff and the SPA's readiness for the full journey is not independently verified here.

**Most risky issues:**
1. Public API has **no authentication** — intentionally out of scope for M9, but the CORS code and review API take `actor` verbatim from the request body. Any exposed deployment is a public write surface for curation unless guarded at the network level.
2. Review API's `actor` is **asserted, not authenticated** — an identity claim, not proof.
3. The breadth of new/changed files (55 staged diffs, ~90 untracked files) indicates a large in-progress cut; some modules are clearly still being wired (e.g. frontend `App.vue` diff is large and not yet reviewed here).

**Ready for:** backend demo of matching + review flow, and real-data testing against the existing PostgreSQL dataset. **Not yet ready for:** production exposure without auth/CORS tightening, and not proven for autonomous country-wide discovery from zero seeds against a live search backend.

## 4. ARCHITECTURE & DEPENDENCY MAP

**Entry points:**
- App: `api/app.py:create_app()` → `app` (FastAPI). Routers: `recommendations`, `scholarships`, `review`.
- Matching: `api/routers/recommendations.py:get_recommendations()` → `MatchingService(session).match(profile)` → `ScholarshipIntelligenceEngine` (Filter→Score→Rank→Explain) → ` ScholarshipRepository.get_all_approved()` (public filter).
- Scholarships read: `api/routers/scholarships.py` → `ScholarshipRepository.search_approved()` / `get_published_by_id()` → `public_filter()`.
- Review: `api/routers/review.py` → `ReviewService(session)` (approve/reject/correct/request_correction/approve_candidate/reject_candidate; queue; metrics; review_packet).
- Ingestion pipeline: `services/ingestion/orchestrator.py:run_pipeline()` → load → clean → `_invoke_client` (DeterministicLLMClient) → validate → `persist_scholarship()` → `ScholarshipMapper.to_orm()` → `ScholarshipRepository.save()` (dedup).
- Exploration: `services/exploration/engine.py:CountryExplorationEngine.run()` → seed frontier (WebSearchSurface + seeds + known sources) → `_frontier_loop` → `_process_candidate` (analyze → classify → provider_resolver → authority_resolver → verifier → register_source / register_needs_review → acquisition → expand_links → mark_done). Acquisition reuses `run_pipeline` via `AcquisitionService.acquire_from_source()`.
- Acquisition service: `services/exploration/acquisition_service.py:acquire_from_source()` → GenericPlaywrightConnector discover → rank_candidate_urls → page_intent → listing_guard → `run_pipeline()` → `_persist_with_dedup()`.

**Key shared kernel:**
- `services/domain/vocabulary.py` — single source of truth for DEGREE/FUNDING_TYPE/EXPERIENCE/SCHOLARSHIP_TYPE. Imported by API schemas, ingestion validator, matching normalizer/validator, review quality, mapper, real extractor.

## 8. BUG & RISK REGISTER

### B01 — PUBLIC WRITE SURFACE WITHOUT AUTH (Critical)
- **Files/functions:** `api/app.py` (no auth middleware); `api/routers/review.py` (actor from request body, recorded verbatim).
- **Evidence:** Review router accepts `actor` string from JSON body; app has no authentication middleware; CORS only enabled if `POLARIS_ALLOWED_ORIGINS` set (empty = disabled).
- **Impact:** If API is network-exposed, anyone can approve/reject/correct records and submit candidates, with actor identity only claimed, not verified.
- **Reproduction (safe):** `POST /api/v1/admin/review/scholarships/{id}/approve` with `{"actor":"attacker","reason":"..."}` — succeeds if record in approvable state.
- **Recommendation:** Treat as out of scope only if deployment is private/network-restricted. For any public exposure, add auth and derive `actor` from authenticated principal, not request body. This is an explicit M9 scope decision, not a new finding, but it is the highest-risk open item for exposure.

### B02 — REVIEW ACTOR IS CLAIMED IDENTITY, NOT AUTHENTICATED (High)
- **Files/functions:** `services/review/service.py` (actor stored as given); `api/routers/review.py`.
- **Impact:** Audit trail records who *claimed* to act, not who was authenticated. Fine if auth added later and populates actor from context; misleading if relied upon today as non-repudiation.
- **Recommendation:** Document clearly; when auth lands, populate actor from request context only.

### B03 — FRONTEND APP.VUE IS A LARGE UNREVIEWED DIFF (High)
- **Files:** `frontend/src/App.vue` (701-line diff), plus many new components/stores/router.
- **Impact:** Hard to assert product readiness from this audit; regressions or broken wiring could be present.
- **Recommendation:** Build `frontend/dist`, run `npm test`, and smoke the SPA against the API before any demo/expose.

### B04 — DISCOVERY NOT PROVEN AGAINST LIVE SEARCH (High for discovery claims)
- **Files/functions:** `services/exploration/engine.py`; `services/exploration/search/`; `services/exploration/surfaces/web_search.py`.
- **Evidence:** E2E loop test uses `FakeSearchProvider`/`FakeAnalyzer`.
- **Impact:** "Country exploration discovers new sources" is architecturally present but not proven end-to-end with a real search backend in the test suite.
- **Recommendation:** Wire a real (or recorded) search provider for a smoke discovery run against a low-risk country, or explicitly label discovery as mock-validated until then.

### B05 — DETERMINISTIC EXTRACTION, NO LIVE LLM (Medium/High depending on expectations)
- **Files/functions:** `services/ingestion/real_extractor.py` (DeterministicLLMClient); `extractor.py` (LLMClient interface).
- **Impact:** If stakeholders expect LLM-based extraction, it is not wired. The interface is ready; implementation is heuristic.
- **Recommendation:** Clarify whether an LLM client is intended next; if so, implement a concrete `LLMClient` and keep the deterministic client as fallback/ghost.

### B06 — COVERAGE RATCHET BELOW 90% WITH KNOWN GAPS (Medium)
- **Files:** `pyproject.toml` coverage config; root metric JSONs.
- **Evidence:** Config comment states honest measurement 85.60% with gaps in `strategy_factory`, `generic_playwright`, discovery, country_orchestrator, mext_connector.
- **Impact:** Coverage gate is set below the honest number as a ratchet, not a pass; risk areas are acknowledged.
- **Recommendation:** Accept as intended ratchet; track gaps to 90% as real work, not test spam.

### B07 — RUFF DEBT ACKNOWLEDGED (Low/Medium)
- **Evidence:** V0.1 report names inherited Ruff debt as a blocker addressed in §11.
- **Recommendation:** Run `ruff check` in CI; not re-verified here.

### B08 — MIGRATION + MODEL CONSTRAINT DUALITY (Low)
- **Files:** `scholarship_version.py` declares UNIQUE constraint; migration `c4d5e6f7a8b9` also creates it; both exist so `create_all` and migrations agree (by design, per code comment).
- **Impact:** Low — intentional. Risk if one drifts.
- **Recommendation:** Keep the dual declaration; the model constraint is the development-path authority, migration is the migration-path authority.

### B09 — ROLLING DEADLINE STATE NOT RE-EVALUATED (Low, by design)

- **Impact:** A page that later becomes date-bound would stay "rolling" until manual sweep or code change.

### B10 — MEXT CONNECTOR STILL FALLS BACK TO `[entry_url]` ON DISCOVERY FAILURE IN ONE BRANCH (Medium)
- **Files:** `services/ingestion/connectors/government/mext_connector.py` `discover()` except-block returns `[str(self.config.url)]`.

- **Impact:** A failed MEXT discovery could hand the portal page to the extractor as though it were a scholarship link (the exact class of failure acquisition policy now prevents at extract time, but the connector still misreports).
- **Recommendation:** Align MEXT connector discovery failure behavior with generic connector (return `[]`).
